# Подключение OpenAI к Intentive

AI-ядро уже реализовано. Нужно создать ключ OpenAI API, добавить его в `.env.local` и перезапустить приложение. Передавать ключ в чат, браузер или Git не требуется.

## 1. Создать проект и ключ

1. Открой [OpenAI Platform](https://platform.openai.com/) и войди в аккаунт.
2. В настройках выбери или создай отдельный проект для Intentive.
3. Проверь Billing и доступный баланс API, затем настрой бюджет/уведомления и доступ к модели в проекте. Фактические условия оплаты и лимиты проверяй в своём аккаунте; приложение не создаёт платёжные настройки автоматически.
4. В разделе API keys выбранного проекта создай секретный ключ. Сохрани его сразу в `.env.local` по инструкции ниже. Для restricted key нужен доступ к созданию Responses.

OpenAI рекомендует хранить API-ключи на сервере через переменные окружения и разделять окружения по проектам. См. [официальный Quickstart](https://developers.openai.com/api/docs/quickstart) и [настройки production-проекта](https://developers.openai.com/api/docs/guides/production-best-practices).

## 2. Добавить настройки на Windows

В корне проекта рядом с `package.json` создай `.env.local`. Можно скопировать `.env.example`, если `.env.local` ещё не существует:

```powershell
if (-not (Test-Path -LiteralPath .env.local)) {
  Copy-Item -LiteralPath .env.example -Destination .env.local
}
```

Открой `.env.local` в редакторе и заполни:

```dotenv
OPENAI_API_KEY=вставь_свой_секретный_ключ
OPENAI_MODEL=gpt-6-luna
AI_RECOMMENDATION_ROLE=select
AI_TIMEOUT_MS=25000
AI_CANDIDATE_LIMIT=8
AI_DEMO_ENABLED=false
```

`OPENAI_API_KEY` не должен иметь префикс `NEXT_PUBLIC_`. `.env.local` исключён из Git; в репозитории сохраняется только пустой шаблон `.env.example`.

Начальная модель — `gpt-6-luna`: поддерживает Responses API и Structured Outputs. Если она недоступна проекту, укажи в `OPENAI_MODEL` доступную модель с этими возможностями и поддержкой `reasoning.effort=low`. Модель заменяется без изменения store, графа и интерфейса. [Документация GPT-6 Luna](https://developers.openai.com/api/docs/models/gpt-6-luna).

## 3. Запустить и проверить

```powershell
npm run dev
```

Если dev-сервер уже работал, останови его и запусти снова после изменения `.env.local`.

Открой «Моё развитие» и нажми **Подобрать шаг с AI**. До нажатия показывается расчётный подбор, запрос в OpenAI не выполняется. После успешной проверки появится **Ответ получен**. Выбор модели может совпасть с исходным подбором — это нормальный результат.

В Network браузера запрос идёт только в `/api/recommendations`. В JSON-ответе успех обозначен `source: ai`, резервный результат — `source: fallback` и `fallbackReason`. Сам OpenAI API вызывается сервером. Ключ не содержится в запросе браузера или ответе маршрута.

Проверка без ключа тоже полезна: кнопка должна вернуть сообщение о ненастроенном OpenAI и сохранить расчётные рекомендации. Автотесты не требуют ключа и не выполняют платные запросы:

```powershell
npm run test:ai
npm test
npm run build
```

## 4. Настроить роль AI

| Настройка | Поведение |
|---|---|
| `AI_RECOMMENDATION_ROLE=select` | AI выбирает и упорядочивает 1–3 шага из проверенного пула |
| `AI_RECOMMENDATION_ROLE=explain` | Состав и порядок расчётных шагов сохраняются; AI выбирает и упорядочивает факторы объяснения |
| `AI_CANDIDATE_LIMIT=8` | Первые 8 допустимых вариантов по расчётному ранжированию; разрешено 3–12 |
| `AI_TIMEOUT_MS=25000` | Бюджет выполнения графа, разрешено 100–30000 мс; после таймаута — fallback |
| `OPENAI_MODEL` | Модель OpenAI, по умолчанию `gpt-6-luna` |

AI возвращает ID активностей и фактов вместе с персональным текстом на русском: общий разбор `summary`, объяснение `explanation` и практический совет `firstStep` для каждой активности. Полный текст передаётся в Zustand и отображается сразу, без раскрытия карточки. Сервер проверяет структуру, непустой текст, размеры и допустимость выбора; фактическая точность каждой фразы автоматически не гарантируется. Комментарий AI визуально отделён от чисел и прогноза ядра. Модель не меняет цель, историю или навыки.

Structured Outputs задаёт форму ответа, но не гарантирует корректность его смысла. Поэтому дополнительно проверяются принадлежность к пулу кандидатов, уникальность выбора, допустимость каждого факта и наличие факторов роли/цели, разрывов и истории. [Официальное руководство Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs).

## 5. Что происходит на сервере

Маршрут загружает исходный датасет и воспроизводит разрешённые действия текущей демосессии — начало и завершение активностей. Браузер не передаёт готовые баллы, уровни навыков или собственный список кандидатов. Сервер пересчитывает подбор и запускает LangGraph:

```text
prepare → choose через OpenAI → validate → AI-результат
                 ошибка / таймаут / неверный ответ → расчётный fallback
```

В OpenAI уходят названия кандидатов, факторы, подтверждённые аргументы и введённые пользователем интересы. Поля `full_name`, `employee_id`, `manager_id`, весь датасет и сырая история в модель не передаются. Свободный текст интересов передаётся как есть, поэтому не добавляй туда персональные данные. Передаётся `store: false`; это не утверждение об отсутствии всех служебных журналов у провайдера.

Используются LangGraph для оркестрации и прямой HTTP-вызов Responses API через `fetch`. Второй SDK устанавливать не нужно. Ключ не логируется, ошибки API не возвращаются клиенту целиком. Повторных запросов к модели в рамках одного запуска нет. Браузер отменяет запрос при смене профиля, предпочтений или истории и отбрасывает поздний ответ даже при неудачной отмене.

## 6. Ошибки подключения

| Результат | Что проверить |
|---|---|
| `not_configured` | Ключ заполнен именно в `.env.local` в корне, dev-сервер перезапущен |
| `provider_error` | Ключ действителен, проект имеет доступ к модели и API-балансу; сеть достигает `api.openai.com` |
| `timeout` | Ответ не уложился в бюджет; попробуй сократить пул до 3–5 кандидатов |
| `invalid_output` | Ответ модели нарушил контракт; используются расчётные рекомендации |
| HTTP 400 | Некорректная цель или журнал действий; при несовместимом старом состоянии перезагрузи демосессию |
| HTTP 403 | Нужен запрос из самого приложения; production-демо по умолчанию выключено |
| HTTP 429 | Локальный лимит приложения: 10 запросов/минуту и максимум 2 одновременно на процесс |
| `no_candidates` | Подходящих шагов нет; модель не вызывается |

На стороне OpenAI HTTP 401 обычно связан с аутентификацией, а 429 — с частотой запросов либо квотой. В интерфейс эти сведения специально не выводятся вместе с сырым ответом провайдера. [Официальные коды ошибок](https://developers.openai.com/api/docs/guides/error-codes).

## 7. Локальная production-проверка

Для `npm run dev` флаг `AI_DEMO_ENABLED` не нужен. Для локального `npm run build` → `npm run start` поставь `AI_DEMO_ENABLED=true` в `.env.local` и перезапусти сервер. Без флага production-маршрут возвращает 403.

Демопереключатель сотрудника не является авторизацией. Перед публичным развёртыванием нужны серверная идентификация пользователя, проверка доступа к профилю, постоянное хранение и распределённые лимиты запросов. Same-origin проверка и локальный лимит этого не заменяют. Не включай production-демо на публичном сервере с платным ключом вместо реализации доступа.

## Где менять реализацию

- `server/ai/config.ts` — модель, режим, таймаут, размер пула и версия AI-политики.
- `server/ai/graph.ts` — узлы LangGraph, подготовка контекста и проверка выбора.
- `server/ai/provider.ts` — серверная точка импорта провайдера.
- `server/ai/openai-transport.ts` — формат OpenAI Responses API и системные инструкции.
- `server/ai/context.ts` — восстановление сессии из серверных данных и журнала действий.
- `core/ai/contracts.ts` — контракты запроса, решения модели и результата.
- `stores/ai-actions.ts` — состояния запроса, отмена и защита от устаревшего ответа.

Смена цели и расчётного ранжирования по-прежнему настраивается через `core/config.ts`; она не требует изменения OpenAI-провайдера.

## Где увидеть ответ и как проверить соединение

Откройте главную «Моё развитие» → блок «AI-наставник» → «Подобрать шаг с AI». Ключ сам по себе не запускает запрос. Ответ появляется в этом блоке и карточках под ним. Базовый подбор до запроса или при ошибке отдельно обозначен и не выдаётся за результат модели.

Интерфейс различает неверный ключ (`authentication`), исчерпанную квоту (`quota`), частоту запросов (`rate_limit`), недоступную модель (`model_unavailable`), отклонённые параметры (`provider_configuration`), сетевую ошибку и таймаут. Сырой ответ провайдера и секреты не отображаются.

Для независимой проверки выполните `npm run diagnose:ai`. Это один реальный запрос с фиксированным нейтральным текстом через тот же транспорт Responses API; данные проекта не читаются и не отправляются. Успешный результат — `connected: true`. Проверка может расходовать API-баланс и не оценивает качество карьерного подбора. `productionDemoEnabled: false` не мешает `npm run dev`, но запрещает AI-запросы приложения при `npm run start`. После изменения `.env.local` перезапустите сервер.

Подробный текст требует большего времени: бюджет графа по умолчанию 25 секунд, максимум 30; клиент ждёт до 35 секунд, маршрут — до 40. Это верхние пределы, не искусственная задержка. Если в старой .env.local стоит AI_TIMEOUT_MS=8000, обновите значение до 25000 и перезапустите dev-сервер. Ответ быстрее 10 секунд при таком объёме текста не гарантирован.
