# Intentive Career Quest

Веб-платформа для персонального развития сотрудников. Проект анализирует профиль, навыки, карьерную цель и историю участия, чтобы рекомендовать следующие шаги развития и объяснять их пользу. Для HR предусмотрен обзор компетенций и вовлечённости сотрудников.

## Цель

Связать обучение с реальной карьерной траекторией сотрудника, учитывать его интересы и сделать рекомендации понятными и добровольными.

## Реализованный flow

1. Приложение загружает и проверяет 200 синтетических профилей из Career Quest Dataset.
2. В настройках Account можно найти тестового сотрудника по имени или ID.
3. Выбранный профиль отображает роль, грейд, отдел, формат работы и карьерную цель.
4. Для каждого сотрудника отдельно хранятся выбранные предпочтения в рамках текущей сессии.
5. Сотруднику доступны разделы My development, Skills & trajectory и Activities.
6. Профиль из Human Resources автоматически получает дополнительный раздел HR overview.

На странице Activities работает демосценарий начала и завершения обучения с обновлением навыков и прогресса. Остальные рабочие страницы пока без содержимого. Авторизация, постоянное хранение и рекомендательная логика ещё не подключены.

## Запуск

```bash
npm install
npm run dev
```

Приложение откроется на [http://localhost:3000](http://localhost:3000).

## Основа данных — шаг 1

Реализованы схемы Zod для всех четырёх файлов, импорт JSON/CSV, проверка связей и производные индексы. При запуске сервер загружает и проверяет весь стартовый набор. Расчётное ядро добавлено на шаге 2, клиентский Zustand и сценарий выполнения — на шаге 3 ниже. Рекомендации и HR-аналитика ещё не реализованы.

Структура:

- `core/domain/schemas.ts` — схемы и выведенные из них TypeScript-типы.
- `core/dataset/import.ts` — полный импорт и добавление проверочных профилей/истории.
- `core/dataset/csv.ts` — CSV с BOM, CRLF, кавычками и перестановкой колонок.
- `core/dataset/validate.ts` — уникальность ID, ссылки, роли/грейды, даты и ограничения записей.
- `core/dataset/indexes.ts` — индексы по ID, роли/грейду, сотруднику и мероприятию.
- `server/repositories/dataset.ts` — серверная загрузка файлов.
- `lib/employees.ts` — совместимые экспорты для существующего UI.

### Контракт импорта

`importDataset({ employees, events, skills, activityHistoryCsv })` принимает JSON-объекты или текст JSON и текст CSV. Возвращает новый набор с `meta`, `proficiency_scale`, `employees`, `skills`, `role_profiles`, `events`, `activity_history` и `warnings`.

`importSupplement(base, { employees?, activityHistoryCsv? }, conflicts?)` добавляет профили и/или историю к проверенному набору. Профили передаются в исходном формате `{ meta, employees }`, история — CSV с заголовком. Новые ID не ограничены диапазоном стартового набора. Можно добавлять только историю для существующих сотрудников. Ссылки проверяются после объединения, поэтому новый сотрудник и его история могут прийти вместе.

Режим конфликтов по умолчанию — `reject`. Явный `replace` заменяет целую запись по `employee_id` или `record_id`; существующая история сотрудника сохраняется и повторно проверяется. Повторы ID внутри одного входного файла запрещены в обоих режимах. Ошибка выбрасывает `DatasetValidationError` с массивом `issues`: источник, путь поля, сообщение. Исходный набор не изменяется даже при неуспешном импорте.

Все JSON-файлы должны иметь одинаковые `dataset`, `version`, `as_of_date`. Дата среза берётся из метаданных, а не из системных часов. Отсутствующие навыки остаются отсутствующими в исходном профиле; расчётное ядро трактует их как уровень 0.

Импорт пока программный: загрузчик файлов в интерфейсе, HTTP endpoint и постоянное сохранение не добавлены. Успешный результат явно передаётся вызывающему коду; автоматической замены глобального состояния нет.

### Особенность стартового набора

В README датасета повтор после завершения разрешён только для `EV_036`, однако исходная история содержит 544 повторных участия в обязательном комплаенсе `EV_001–003`. Импорт сохраняет все записи и возвращает предупреждение для каждого такого повтора. Повтор обязательного `compliance` допускается с предупреждением; для остальных мероприятий, кроме `EV_036`, повтор после завершения — ошибка. Исходные файлы не исправляются автоматически.

Дата в истории означает дату сессии или зачисления, отдельной даты завершения нет. Импорт сохраняет эту семантику. Историческая доступность не проверяется по текущему грейду или текущим навыкам: профиль мог измениться после участия.

## Расчётное ядро — шаг 2

Чистые функции без React, Zustand, запросов к AI и изменения исходных данных:

- `core/skills/calculate.ts` — актуальные навыки, журнал начислений, прогноз эффекта мероприятия.
- `core/trajectory/calculate.ts` — цель, требования текущей роли и цели, разрывы и покрытие требований.
- `core/activities/availability.ts` — доступность добровольного следующего шага с причинами ограничений.
- `core/development.ts` — объединённый расчёт по сотруднику.

`createDevelopmentCalculator(dataset)` принимает проверенный датасет и один раз строит индексы. Его метод `calculateEmployee(employeeId, selectedGoal?)` возвращает навыки, траекторию и доступность всех мероприятий с гипотетическим эффектом. После импорта или изменения истории калькулятор создаётся заново. На шаге 3 он подключён к Activities через мемоизированный селектор.

### Навыки

База — навыки последней оценки, дополненные нулями для отсутствующих навыков каталога. Учитываются только записи этого сотрудника со статусом `completed`, датой строго после `last_review_date` и не позднее `meta.as_of_date`. Порядок — дата, затем `record_id` для однозначного результата в один день.

Формула для каждого развиваемого навыка: `after = max(before, min(5, max_level, before + gain))`. Мероприятие не снижает достигнутый уровень. Незавершённое участие не начисляет частичный прирост; `score` и оценка мероприятия не меняют заданный `gain`. Регулярный клуб учитывается по отдельным записям участия. Комплаенс с пустым `develops_skills` ничего не начисляет.

Каждое учтённое завершение содержит ID записи и мероприятия, эффективную дату, уровни до/после и фактический прирост. Расчёт всегда повторяется от исходной оценки: повторный вызов не начисляет прогресс второй раз. За уникальность записей отвечает импорт шага 1.

**Ограничение исходных данных:** в CSV нет отдельного `completed_at`. Для старых завершённых записей используется `date` как приближение даты завершения, что явно обозначено `dateSource: activity_date_proxy`. Для self-paced это дата зачисления; точный момент завершения восстановить нельзя. Старые записи на дату оценки считаются уже учтёнными. На шаге 3 новые завершения получают `completed_at`, который используется вместо даты зачисления.

### Цель и прогресс

Приоритет: явно переданная цель → цель профиля → предварительный следующий грейд текущей роли. Для Lead без цели используется текущая роль/грейд. `selectedGoal: null` явно снимает цель профиля и включает предварительную траекторию; отсутствие аргумента сохраняет цель профиля. Источник цели возвращается отдельно и не меняет профиль. Неизвестная комбинация роли/грейда вызывает ошибку.

По каждому требуемому навыку возвращаются текущий и необходимый уровни, `gap = max(0, required - current)` и признак критичности. Покрытие требований: `sum(min(current, required)) / sum(required) × 100`. При нулевой сумме требований результат — 100%. Ядро не округляет процент; отображение округляет отдельно.

Избыток одного навыка не закрывает недостаток другого. `criticalRequirementsMet` и `allRequirementsMet` возвращаются раздельно: выполнение требований по навыкам не является решением о повышении. Текущая роль и целевая траектория рассчитываются отдельно.

### Доступность мероприятий

Для добровольного следующего шага проверяются обязательность, текущие роль и грейд сотрудника, prerequisites по пересчитанным навыкам, прошлое завершение, активное участие и наличие сессии. `EV_036` допускает повтор после завершения, но не параллельное активное участие. `self_paced` доступен без сессий; для остальных форматов выбирается ближайшая дата не раньше среза.

Все причины возвращаются кодами, а для нехватки prerequisite — также уровни навыка. Пропуски и отказы не блокируют участие навсегда: их влияние на ранжирование относится к будущему шагу рекомендаций. Недельный бюджет и предпочтения формата здесь не превращаются в жёсткие ограничения. Целевая роль не подменяет текущую роль при проверке аудитории мероприятия.

Гипотетический эффект возвращается и для недоступных мероприятий, отдельно от `available`: это прогноз, а не начисление или рекомендация. Мероприятие без прироста к выбранной цели может оставаться доступным. Обязательное мероприятие исключается только из добровольных следующих шагов; этот результат не запрещает выполнять уже назначенное обучение.

Проверка обоих шагов: `npm run test:core` — 21 тест, включая расчёт всех 200 профилей, границы оценки/даты среза, caps, повторяемость, смену роли, критические разрывы, расписание и перерасчёт после добавленного завершения.

## Zustand и выполнение активности — шаг 3

`stores/career-store.ts` создаёт отдельный store на экземпляр Provider. `stores/user-store.ts` сохраняет прежний путь импорта. Store содержит один снимок датасета, выбранный ID сотрудника, предпочтения по сотрудникам и счётчики изменений данных/настроек. Профиль, текущие предпочтения и расчётный прогресс выбираются селекторами, без дублирования в состоянии.

`stores/selectors.ts` предоставляет стабильные ссылки для React/Zustand. `createDevelopmentSelector()` создаётся на потребителя; пересоздаёт калькулятор при изменении датасета и пересчитывает выбранного сотрудника при изменении его настроек. `useDevelopment()` подключает его к интерфейсу. Нет глобального серверного store и общего кэша между сессиями.

Действия:

- `selectEmployee(id)` — меняет демопрофиль; неизвестный ID игнорируется.
- `updatePreferences(patch)` — обновляет предпочтения выбранного сотрудника. `grow` выбирает текущую роль/грейд, `promotion` — следующий грейд, а для `change_role` в настройках выбирается конкретная роль/грейд. Без конкретной цели используется предварительная траектория.
- `startActivity(employeeId, eventId)` — проверяет доступность и создаёт участие. Повторное начало активного участия возвращает его ID. Self-paced можно начать сразу; сессию — только в дату среза, не заранее. Самостоятельно назначить обязательное обучение нельзя.
- `completeActivity(employeeId, recordId)` — завершает существующее `in_progress` или `overdue` участие, устанавливает 100% и точную дату завершения. Повторное завершение той же записи не изменяет store. Для нерегулярных мероприятий повторное завершение через другую запись также запрещено.

Оба действия участия возвращают `{ ok, recordId }` либо `{ ok: false, error }`. Если выбранный профиль успел измениться, команда отклоняется. Это защита от ошибки интерфейса, а не серверная авторизация.

`core/activities/complete.ts` сохраняет исходную дату участия. `completed_at` — необязательное расширение внутренней модели, исходный CSV и его заголовок не меняются. Новое завершение в день оценки считается действием после уже загруженной оценки; старая CSV-история на ту же дату повторно не начисляется. Дата действия берётся из `meta.as_of_date`, поэтому демо воспроизводимо.

### Проверка в интерфейсе

Открыть Activities → выбрать активное обучение → Mark completed. Запись перейдёт в Recently completed, появятся изменения навыков и обновится покрытие требований. Для нового обучения выбрать Start activity у доступного self-paced мероприятия. Переключение профиля сохраняет изменения отдельно для каждого сотрудника.

На этом этапе проверенный **синтетический** набор передаётся в клиентский Provider целиком для переключения демопрофилей. Файлы исходного набора не меняются. Изменения хранятся в памяти до перезагрузки страницы, независимо для каждой вкладки. Производственное разграничение доступа и серверное постоянное хранение пока отсутствуют; перед реальными данными этот механизм должен быть заменён персональными серверными выборками и проверкой прав.

`npm test` — все 28 тестов трёх шагов. `npm run test:store` — 7 тестов store/завершения: изоляция сессий, стабильность селекторов, настройки по сотрудникам, повторные команды, запрещённые переходы, смена профиля и точная дата завершения. AI-рекомендации и HR-аналитика в этот шаг не входят.
